# Ограничения

Ограничения определяют область применения `rib` и должны учитываться при
проектировании сборочного конвейера.

## Формирование образа

- Поддерживаются только добавление файлов через `COPY` и изменение runtime-
  metadata. Команда `RUN` и произвольный синтаксис Dockerfile отсутствуют.
- Установка пакетов и whiteout-слои для удаления файлов базового образа не
  поддерживаются.
- Символические ссылки и специальные файлы в source-пути `--copy` отклоняются.
- Абсолютные Windows-пути вида `C:\project\artifact.exe` нельзя использовать
  как source в `--copy`, поскольку двоеточие разделяет source и destination.
  Используйте относительный путь или запускайте команду из соответствующего
  каталога.
- Один запуск формирует manifest для одной платформы. Multi-platform index
  должен создаваться отдельным инструментом или последующим этапом.
- `scratch` не содержит libc, CA certificates, shell и других runtime-файлов.
  Необходимые зависимости добавляются явно.

## Кэширование

- Без `--cache` скачанные base-blobs удаляются после завершения процесса.
- `--cache` сохраняет только скачанные слои базового образа. Построенные
  `COPY`-слои между запусками не кэшируются.
- Общий каталог кэша не предназначен для конкурентной записи несколькими
  процессами.
- Прямой push в registry использует наличие blob'ов и cross-repository mount;
  поэтому локальный кэш не требуется для обычного повторного push в тот же
  registry.

## Интеграция с Cargo

- Artifact, платформа и base image задаются явно.
- Cross-compilation, установка target и выбор binary target не выполняются
  автоматически.
- Архитектура и способ линковки artifact не анализируются.
- При неоднозначном workspace пакет необходимо выбирать запуском команды из
  каталога соответствующего package.

## Registry и публикация

- Несколько целей `--to` обрабатываются последовательно и не образуют общую
  транзакцию.
- При ошибке поздней цели уже опубликованные ранние цели не откатываются.
- Повторная попытка передачи blob начинается с начала; resumable upload не
  поддерживается.
- Docker credential helpers не запускаются. Читается только секция `auths`
  Docker config либо явные credentials CLI.
- Встроенные signing, SBOM и provenance отсутствуют. Manifest digest выводится
  в stdout для передачи внешнему инструменту, например `cosign`.
- Ctrl-C обрабатывается кооперативно; отдельного обработчика SIGTERM нет.

## Возможные направления развития

- кэширование построенных `COPY`-слоёв и поддержка параллельного кэширования для нескольких экземпляров приложения;
- формирование multi-platform index;
- registry-native referrers для SBOM и provenance;
- resumable upload;
- внешние credential providers и cloud workload identity;
- координация нескольких целей публикации;
